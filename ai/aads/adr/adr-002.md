# ADR-002 — Operational Completion Architecture (AADS 0.3.0)

**Status:** Aceita  
**Data:** 2026-08-05  
**Versão:** 0.3.0

---

## Contexto

Após as fases 0.1.x–0.2.x, o AADS possuía Engine, Completion Model e Cursor Rules, mas faltavam workflows por tipo de trabalho e standards portáteis para novos projetos. Uma lista longa de microdocumentos foi proposta; criar todos geraria duplicação e violaria a fonte única da verdade.

## Problema

Como completar o AADS para uso real em múltiplos projetos e IAs sem fragmentar autoridade nem reinventar o Operating Model.

## Alternativas

1. Criar um arquivo por tópico da lista (40+ docs) — alto ruído, alta duplicação.
2. Manter só Engine e Features — lacunas operacionais (Release/Hotfix/Recovery).
3. **Completar com workflows/standards essenciais + consolidação deliberada** — escolhida.

## Decisão

1. Preservar Constitution, Source of Truth Map e Operating Model como canônicos.
2. Adicionar workflows faltantes: Bugfix, Hotfix, Research/Spike, Refactor, Release, Maintenance, Recovery.
3. Adicionar standards: versioning, testing, naming, architecture definition, prompt management, risk, project structure.
4. Adicionar `engine/ai-recovery-protocol.md` e compliance checklist.
5. Consolidar lifecycles de artefatos em `standards/artifact-lifecycles.md`.
6. Mover relatórios históricos para `reports/` (não-normativos).
7. Publicar `INDEX.md` + `DOCUMENT-STANDARD.md`.
8. Não duplicar Decision Tree / Context Loading (permanecem no Operating Model).

## Consequências

### Positivas

- Cobertura operacional por tipo de trabalho.
- Navegação clara para novas IAs/projetos.
- Menos ambiguidade Release/Hotfix/Recovery.

### Negativas

- Mais arquivos (mitigado por INDEX e consolidação).
- Necessidade de manter links cruzados.

## Impactos

- Versão AADS **0.3.0** — primeira versão operacional completa (ainda pré-1.0).
- Cursor Rules 0.2.2 permanecem ACTIVE FOR VALIDATION; alinhamento fino opcional em 0.3.1.
